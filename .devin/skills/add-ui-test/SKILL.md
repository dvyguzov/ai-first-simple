# Добавление UI-теста

1. **Сначала найди класс этой страницы.** Сценарии одной страницы
   живут в одном классе: новый тест на форму логина — это новый
   метод в `LoginTest`, а не новый класс. Новый класс заводи только
   когда появилась новая страница. Проверка: список файлов в
   `src/test/java/qa/aifirst/` и `docs/kb/selenide.md` (раздел
   «Где лежат тесты и конфиг?»).
2. Новый класс (если всё-таки нужен) — в
   `src/test/java/qa/aifirst/`, наследуйся от `TestBase`:
   там общая настройка Selenide и Allure, не дублируй её в тесте.
3. Пиши в Selenide-стиле: `open(URL)`, `$`, `shouldHave` — без
   явных вызовов WebDriver и ручных ожиданий. URL страницы на
   GitHub Pages смотри в `LoginTest`.
4. Один тест = один сценарий: не объединяй разные сценарии
   в один метод.
5. `@DisplayName` на русском — имя теста читается как требование.
6. Эталонный пример — `LoginTest.java`; локаторы, креды и тексты
   формы смотри в `index.html`, не выдумывай.
7. Перед коммитом прогони `./gradlew test` — всё должно быть зелёным.
