# Конвенции тестов

- Каждый тестовый класс наследуется от `TestBase` — там общая
  настройка Selenide и Allure, не дублируй её в тестах.
- Один тестовый класс — одна страница. Новый сценарий добавляй
  новым методом в существующий класс (у формы логина это
  `LoginTest`), а не создавай новый класс. Новый класс заводи
  только под новую страницу. Перед созданием файла посмотри
  `src/test/java/qa/aifirst/` — не дублируй уже существующий класс.
- Selenide-стиль: `open`, `$`, `shouldHave` — без явных вызовов
  WebDriver и ручных ожиданий.
- `click()` без аргументов возвращает `void`, поэтому цепочку
  `click().shouldBe(...)` не пиши: `click()` — отдельной строкой.
- Проверку «показана ошибка» пиши через `cssClass("error")`, а не
  через точный текст: сообщения меняются вместе с продуктом, класс
  остаётся. Точный текст проверяй отдельным тестом.
- Один тест = один сценарий: не объединяй разные сценарии
  в один метод.
- `@DisplayName` на русском — имя теста читается как требование.
